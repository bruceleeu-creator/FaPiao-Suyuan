# 验真与凭证规则设计（含提示词约束）

> 版本：2026-08-31 · 适用：`server/deepseekClient.mjs`（AI 验真 / AI 凭证草稿）
> 原则：**能确定性的绝不交给 AI，交给 AI 的必须圈死范围**。本文档是规则的唯一权威来源，代码注释与本文档同步维护。

---

## 1. 设计总纲：三层防跑偏

| 层 | 职责 | 失败行为 |
|---|---|---|
| L1 确定性规则（代码） | 号码/代码/日期/勾稽等可编程校验，AI 之前执行 | 硬伤直接出结论，不消耗 AI 调用 |
| L2 提示词约束（提示词工程） | 圈死核验范围、封闭枚举、禁止事项、拒答出口 | 模型越界输出会被 L3 拒收 |
| L3 后置质量闸（代码） | JSON 解析、枚举校验、借贷平衡、科目白名单、金额口径 | 任何一项不过 → 拒收并回退本地规则 |

**核心纪律：AI 永远只有建议权，没有定谳权。** 验真结论映射保守（存疑→待验真交人工），凭证不过闸不入流。

## 2. 验真确定性规则（L1，全部有出处）

### 2.1 发票号码与代码

| 规则 | 判定 | 出处 |
|---|---|---|
| 号码 = 8 位数字（税控）或 20 位数字（数电） | 违反 → 硬伤 | 税务总局公告 |
| 数电票（20 位）**不应有发票代码** | 有代码 → 矛盾提示 | 《关于推广应用全面数字化电子发票的公告》：数电票将代码+号码合并为 20 位号码，取消校验码、密码区 |
| 数电票号码第 1-2 位 = 开票年份后两位 | 不符 → 硬伤 | 同上：第 1-2 位代表公历年度后两位 |
| 数电票号码第 3-4 位 ∈ 省级区域代码区间（11-82） | 区间外 → 提示核对 | 同上：第 3-4 位为省级税务局区域代码 |
| 12 位代码第 1 位 = 0 | 违反 → 硬伤 | 税务总局 2020 年第 22 号公告（电子专票编码规则） |
| 12 位代码第 6-7 位 = 开票年份后两位 | 不符 → 硬伤 | 同上：第 6-7 位代表年度 |
| 12 位代码第 11-12 位 = 13 → 电子专票 | 与票面票种矛盾 → 提示 | 同上：第 11-12 位为票种，电子专票为 13 |
| 10 位代码第 8 位 ∈ {1,2,5,7} → 专票 | 与票面票种矛盾 → 提示 | 行业通行票种识别规则（费耘等查验接口文档） |

### 2.2 日期与金额

| 规则 | 判定 | 出处 |
|---|---|---|
| 开票日期 ≤ 今天 | 未来日期 → 硬伤 | 常识核验 |
| 开票日期 ≥ 5 年前 | 更早 → 提示（超出常规核验范围） | 会计档案/核验惯例 |
| 金额 + 税额 = 价税合计（±0.05） | 不符 → 硬伤 | 全国增值税发票查验平台以"号码+日期+价税合计"为查验要素（inv-veri.chinatax.gov.cn） |
| 税率 ∈ {0,1,3,5,6,9,13}% 或 免税/不征税 | 区间外 → 提示 | 增值税现行税率体系 |

### 2.3 AI 语义核验范围（L2，只允许以下四类）

1. 票种与税率匹配（餐饮服务等现代服务业 6%、货物 13% 等明显错配）
2. 项目名称与销方/类别的语义合理性（措辞必须"建议核对"，禁止定性）
3. 票种年代一致性（数电票 vs 税控代码表述矛盾）
4. 金额勾稽补充复核（不重复报告 L1 已列明的算术结果）

### 2.4 结论映射（保守原则）

| AI/规则结论 | 映射 Invoice.verificationStatus | 理由 |
|---|---|---|
| L1 硬伤 | 验真失败 | 确定性规则错误 |
| AI 一致 | 验真通过 | 票面自洽（仍标注非官方） |
| AI 存疑 / 无法判断 | 待验真 | **不硬失败**，交人工复核 |

## 3. 凭证草稿规则（L2 白名单 + L3 三道闸）

### 3.1 借方费用科目白名单（八类映射，依据《企业会计准则》常用费用科目）

| 发票类别 | 科目 |
|---|---|
| 餐饮 | 管理费用-业务招待费 / 销售费用-业务招待费 / 管理费用-职工福利费（员工聚餐） |
| 住宿、交通 | 管理费用-差旅费 / 销售费用-差旅费 |
| 车辆 | 管理费用-车辆使用费 |
| 办公 | 管理费用-办公费 |
| 咨询服务 | 管理费用-咨询顾问费 |
| 广告推广 | 销售费用-广告宣传费 |
| 租赁物业 | 管理费用-租赁费 / 销售费用-租赁费 |

决策草稿 `postingAdvice` 已给出科目路径时**优先沿用**（与状态机既有口径一致）。

### 3.2 贷方科目枚举（封闭）

`其他应付款-员工报销` / `银行存款` / `库存现金`（费用报销场景法定常见贷方）

### 3.3 分录铁律（写入提示词 + 后置校验双重保障）

1. **借贷平衡**：借方合计 = 贷方合计（±0.05）
2. **专票拆分**：票种含"专" → 借费用 = 不含税金额、借`应交税费-应交增值税-进项税额` = 税额；普票 → 借费用 = 价税合计
3. **金额来源封闭**：只能取票面 amount/taxAmount/totalAmount，禁止模型自行计算
4. **科目封闭**：借方 ∈ 白名单 ∪ postingAdvice 路径；贷方 ∈ 枚举
5. **拒答出口**：号码/价税合计/类别缺失或金额 ≤ 0 → 输出 `{"insufficient":true}`，后端尊重拒答并回退本地规则
6. 永远只是草稿：summary 禁止"过账/入账完成"表述

### 3.4 后置质量闸（L3，任一不过即拒收回退）

| 闸 | 校验 | 拒收状态码 |
|---|---|---|
| Q1 | ≥2 条分录且借贷平衡 | `unbalanced` |
| Q2 | 科目全部在白名单/枚举/建议路径内 | `illegal_account` |
| Q3 | 借方合计与票面口径一致（专票=金额+税额，普票=价税合计） | `amount_mismatch` |

## 4. 提示词工程约束（L2 的构造方法）

依据 DeepSeek 官方文档与提示工程最佳实践：

| 手段 | 落地 |
|---|---|
| **JSON Output 模式**（[官方 JSON mode](https://api-docs.deepseek.com/zh-cn/guides/json_mode)） | `response_format: {type:'json_object'}`，官方要求提示词含 "JSON" 字样并给出输出示例（均已满足） |
| **封闭枚举** | 验真 conclusion ∈ {一致,存疑,无法判断}；凭证 direction ∈ {借,贷}；科目/贷方白名单 |
| **负面约束显式化** | "不得编造字段值 / 不得推测真伪 / 禁止空泛表述 / 禁止自算金额" |
| **拒答出口**（防硬造） | 验真"无法判断"；凭证 `insufficient`——宁可拒答不可编造 |
| **few-shot 示例** | 两类提示词各带一个最小输出示例 + 凭证带拒答示例 |
| **范围圈定** | 验真只列四类检查维度，明确"无法联网、只判断票面自洽" |

通用参考：[DeepSeek 官方 Prompt Library](https://api-docs.deepseek.com/zh-cn/prompt-library/)、Anthropic/OpenAI 提示工程指南（角色→规则→schema→禁止→示例 的分层结构）。

## 6. 维护规约

- 修改任何规则**必须同步更新本文档**并在提交信息注明出处
- 新增科目/税率需先在本文档登记，再改 `VOUCHER_ALLOWED_ACCOUNTS` / `deterministicPreCheck`
- 永远不允许：把确定性规则搬进提示词（让 AI 算数）、放开科目白名单、让 AI 结论直接定谳验真失败
