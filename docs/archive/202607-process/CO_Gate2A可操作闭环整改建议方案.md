# CO_Gate2A可操作闭环整改建议方案

> 日期：2026-07-17
> 项目：发票溯源证据链系统
> 结论：Gate 1 已完成展示型骨架，下一步必须转入“可操作闭环”，否则用户看到的仍然只是静态样板页。

## 一、当前判断

当前第一期页面已经能展示产品概念，但还不是一个正常使用者能完成工作的应用。

主要问题不是页面不够，而是缺少从“输入发票”到“风险决策建议”的连续动作：

1. 没有新增发票入口。
2. 没有票面确认、业务追问、证据补充、人工确认等互动环节。
3. AI 介入只停留在静态文案，没有形成可触发、可采纳、可修改、可留痕的模块。
4. 最终建议只展示在 demo 数据里，没有一个明确的“生成风险建议 / 凭证草稿建议”动作和结果页。

## 二、对用户四个问题的直接回答

### 1. 入口在哪？

当前实际入口：

- `/invoices` 发票列表页。
- 但它只是展示固定演示数据，不是真正的录入入口。

建议整改后的入口：

- 在工作台首页和发票列表页增加明显按钮：`录入发票`。
- 新增页面：`/intake` 或 `/invoices/new`。
- 入口包含三种首版方式：
  1. 上传发票文件：允许选择 PDF / 图片，但 OCR 先模拟。
  2. 手工录入票面关键字段：票号、销方、金额、税额、项目、日期。
  3. 选择演示样例：餐饮、住宿、咨询服务、高风险阻断案例，用于快速演示闭环。

### 2. 互动环节在哪里？

当前实际互动：

- 只有页面跳转，没有业务互动。

建议整改后的互动环节：

1. 发票录入：上传或手填。
2. 票面确认：系统模拟 OCR 后，用户确认或修改票面字段。
3. 业务还原追问：系统根据发票类型提出问题，例如餐饮问招待对象、住宿问出差单、咨询问合同和成果物。
4. 证据补充：用户勾选或上传对应证据，首版用模拟附件名即可。
5. AI 初判：系统生成业务场景、证据缺口、风险提示和建议。
6. 人工确认：用户可采纳、修改或退回 AI 结论。
7. 生成风险建议：输出会计、税务、内控、证据和凭证草稿建议。

### 3. 人工智能介入的板块在哪里？

当前实际状态：

- `RiskDashboardPage` 有 AI 采纳率的模拟指标。
- `demoCases` 里有“模拟 AI 结论一致”的静态文案。
- 但没有真正的 AI 工作区。

建议整改后的 AI 介入板块：

1. OCR 模拟 AI：从上传文件或样例中生成票面识别结果。
2. 业务还原 AI：根据票面信息提出动态追问，并生成业务事件对象。
3. 证据匹配 AI：判断已上传材料是否覆盖证据要求，指出缺口和冲突。
4. 风险解释 AI：生成风险卡片、整改建议、置信度和“暂不能判断”原因。
5. 凭证建议 AI：在规则允许时生成凭证草稿建议，但不得自动过账。

UI 上建议新增一个固定区域：`AI 辅助判断面板`，展示：

- AI 当前任务。
- 输入来源。
- 输出结论。
- 置信度。
- 需要用户回答的问题。
- `采纳`、`修改`、`退回` 三个动作。

### 4. 最后生成建议的地方在哪里？

当前实际状态：

- 单张发票详情页的“入账风险”板块展示了固定建议。
- 风险驾驶舱也展示了固定风险卡片。
- 但没有“生成建议”的动作，也没有正式结果页。

建议整改后的最终建议位置：

- 在单张发票流程最后一步新增：`风险决策与凭证草稿建议`。
- 当发票闸门、业务闸门、证据闸门、风险闸门完成后，出现按钮：`生成风险建议`。
- 生成后进入或停留在 `/invoices/:caseId/decision`。

建议结果必须包含：

1. 会计处理建议。
2. 增值税处理建议。
3. 企业所得税处理建议。
4. 其他税种或特殊风险提示。
5. 证据链结论。
6. 风险等级和置信度。
7. 整改建议。
8. 审批要求。
9. 凭证草稿建议。
10. 人工复核记录。

## 三、下一步整改方向

建议把原 Gate 2 拆成一个更贴近用户体验的 Gate 2A：

> Gate 2A：从录入发票到生成风险建议的可操作闭环。

它不替代后续核心对象、状态机和规则引擎，而是先把真实使用路径跑起来。

## 四、建议新增页面和模块

### 1. 新增发票录入页

路径：`/intake`

必须具备：

- 上传控件或上传占位。
- 手工字段录入表单。
- 演示样例选择。
- `开始识别` 按钮。
- 明确提示 OCR 当前为模拟。

### 2. 新增流程工作台

路径：`/invoices/:caseId/workflow`

建议用步骤条表达：

1. 发票输入。
2. 票面确认。
3. 业务追问。
4. 证据补充。
5. AI 风险初判。
6. 人工复核。
7. 生成建议。

每一步都要有可点击动作，不能只展示文字。

### 3. 新增 AI 辅助判断面板

可以放在流程页右侧或每一步下方。

必须具备：

- 当前 AI 任务。
- AI 输出内容。
- 置信度。
- 问题清单。
- 用户回答区。
- 采纳、修改、退回按钮。

### 4. 新增风险建议结果页

路径：`/invoices/:caseId/decision`

必须具备：

- 四道闸门结果。
- 会计 / 税务 / 内控 / 证据结论。
- 风险卡片。
- 整改建议。
- 凭证草稿建议。
- 最终状态：可生成草稿、待人工确认、禁止生成、暂不能判断。

## 五、建议的数据和状态整改

当前数据对象基本够用，但缺少“用户操作态”。建议新增：

1. `InvoiceWorkflowSession`
   - 当前步骤。
   - 当前状态。
   - 已完成步骤。
   - 操作日志。

2. `AiIntervention`
   - 介入阶段。
   - 输入摘要。
   - 输出摘要。
   - 置信度。
   - 需要追问的问题。
   - 用户采纳状态。

3. `UserActionLog`
   - 操作人。
   - 操作动作。
   - 操作前状态。
   - 操作后状态。
   - 时间。
   - 备注。

4. `DecisionDraft`
   - 建议版本。
   - 会计建议。
   - 税务建议。
   - 证据建议。
   - 凭证草稿。
   - 最终处理状态。

## 六、首轮不要做的事

为了保持一期边界，Gate 2A 仍然不做：

1. 不接真实 OCR。
2. 不接真实发票验真。
3. 不接真实凭证接口。
4. 不做完整手机端。
5. 不自动过账。
6. 不自动申报。
7. 不做登录、多租户、权限体系。
8. 不做复杂后端数据库。

## 七、建议验收标准

Gate 2A 通过标准：

1. 用户从首页或列表页能点击 `录入发票`。
2. 用户能选择或填写一张发票。
3. 系统能模拟 OCR 输出并允许用户确认或修改。
4. 系统能按发票类型提出业务追问。
5. 用户能回答问题和补充证据。
6. 系统能模拟 AI 生成风险初判。
7. 用户能采纳、修改或退回 AI 结论。
8. 系统能生成最终风险建议和凭证草稿建议。
9. 高风险案例不能生成可过账凭证，只能输出阻断或整改建议。
10. 全流程必须有状态变化和操作日志展示。
11. `npm test`、`npm run build` 必须通过。
12. 页面亲测必须能跑通餐饮、住宿、咨询服务至少 1 条完整流程。

## 八、建议优先级

### P0：必须先做

- `录入发票`入口。
- 可操作流程页。
- 模拟 OCR 和票面确认。
- 业务追问和证据补充。
- AI 辅助判断面板。
- 生成风险建议动作。
- 操作日志。

### P1：本轮可做但不强求

- 表单校验。
- 风险建议版本号。
- 三类场景不同追问模板。
- 采纳率、修改率从操作日志中计算。

### P2：后续再做

- 真实文件解析。
- 真实 OCR。
- 真实发票验真。
- 真实凭证接口。
- 权限体系。
- 手机端补资料。

## 九、给 T 的开发策略建议

建议让 T 下一轮只做“前端本地状态闭环”，不要做后端。

技术实现建议：

1. 继续使用 React + TypeScript。
2. 用本地 `useReducer` 或轻量状态模块管理流程状态。
3. 用 mock service 模拟 OCR、追问、证据匹配、风险建议。
4. 先不接数据库，刷新丢失可接受。
5. 保持现有 demoCases，新增一条用户创建的 draft case。
6. 每个按钮动作都要改变状态并写入操作日志。

## 十、最终建议

下一步不要直接进入“更严谨的数据模型”或“更多驾驶舱指标”，而是优先补齐用户指出的真实使用链路：

> 发票录入 -> OCR 模拟识别 -> 票面确认 -> AI 业务追问 -> 证据补充 -> AI 风险初判 -> 人工采纳/修改 -> 生成风险建议与凭证草稿。

只有这条链路可点击、可反馈、可留痕后，这个系统才从展示页变成可用的业务闭环 MVP。
