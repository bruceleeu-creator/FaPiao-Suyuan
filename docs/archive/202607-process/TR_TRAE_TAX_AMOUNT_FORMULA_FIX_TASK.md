# TRAE 税额计算公式修正任务

## 任务背景

用户反馈：录入发票环节税额计算公式不对。Codex 已复核现状：

- 当前 `src/ui/taxCalc.ts` 使用 `税额 = 金额 × 税率`。
- 当前录入页字段为“金额（元）”，普通用户容易按发票票面“价税合计”填写。
- 项目演示数据中，住宿样例 `980 元 / 6% / 税额 55.47` 已经体现“价税合计拆分”口径：
  - 不含税金额 = `980 ÷ (1 + 6%) = 924.53`
  - 税额 = `980 - 924.53 = 55.47`

因此本轮应把录入页修为“价税合计录入，系统自动拆分不含税金额和税额”。

官方依据：

- 国家税务总局相关口径：销售额 = 含税销售额 ÷（1 + 税率或征收率）；税额 = 含税总收入 - 销售额。
- 上海税务问答同样明确：采用销售额和销项税额合并定价时，销售额 = 含税销售额 ÷（1 + 税率）。

## 修正目标

### P1：公式修正

新增或调整税额 helper，使其支持以下口径：

```text
不含税金额 = 价税合计 ÷ (1 + 税率)
税额 = 价税合计 - 不含税金额
```

保留 2 位小数。

验收样例：

| 价税合计 | 税率 | 不含税金额 | 税额 |
| --- | --- | --- | --- |
| 980 | 6% | 924.53 | 55.47 |
| 1860 | 3% | 1805.83 | 54.17 |
| 48000 | 6% | 45283.02 | 2716.98 |
| 1000 | 13% | 884.96 | 115.04 |
| 任意金额 | 0% | 原金额 | 0 |

### P1：录入页字段口径

调整 `src/ui/pages/InvoiceIntakePage.tsx`：

- 把输入框文案从“金额（元）”改成“价税合计（元）”。
- 税额提示文案改为：`税额 = 价税合计 - 价税合计 ÷ (1 + 税率)，保留 2 位小数。`
- 用户输入价税合计和税率后：
  - `form.amount` 应保存“不含税金额”。
  - `form.taxAmount` 应保存“税额”。
  - 页面应显示自动计算出的税额。
- 开始识别后生成的 `invoice.amount` 必须是不含税金额，`invoice.taxAmount` 必须是税额，避免凭证生成时重复加税。

### P1：快速体验样例同步

更新 `InvoiceIntakePage.tsx` 的快速体验样例：

- 餐饮：价税合计 1860，税率 3%，应落入 `amount=1805.83`、`taxAmount=54.17`。
- 住宿：价税合计 980，税率 6%，应落入 `amount=924.53`、`taxAmount=55.47`。
- 咨询服务：价税合计 48000，税率 6%，应落入 `amount=45283.02`、`taxAmount=2716.98`。
- 高风险餐饮同餐饮口径。

如果需要保留演示案例的展示总额，请在录入页内部用本地 UI 字段维护“价税合计”，不要把价税合计误写入 `Invoice.amount`。

### P2：演示数据一致性

复核 `src/data/demoCases.ts`：

- 如果 `invoice.amount` 的系统含义是不含税金额，则修正样例数据，保证 `amount + taxAmount = 用户看到的价税合计`。
- 重点修正当前不一致：
  - 餐饮样例现在 `amount=1860, taxAmount=52.64, taxRate=3%`，不符合任何清晰口径。
  - 住宿样例现在 `amount=980, taxAmount=55.47, taxRate=6%`，税额像是按价税合计拆分，但 `amount` 仍像价税合计。

建议统一改为：

| 样例 | 价税合计 | `invoice.amount` 不含税 | `invoice.taxAmount` |
| --- | --- | --- | --- |
| case-catering-001 | 1860 | 1805.83 | 54.17 |
| case-lodging-001 | 980 | 924.53 | 55.47 |
| case-consulting-001 | 48000 | 45283.02 | 2716.98 |
| case-blocked-001 | 1860 | 1805.83 | 54.17 |
