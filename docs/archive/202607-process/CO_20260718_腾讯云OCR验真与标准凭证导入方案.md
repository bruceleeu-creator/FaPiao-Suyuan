# CODEX_20260718_腾讯云 OCR 验真与标准凭证导入方案

## 一、当前决策

本项目真实接口接入采用 A 路线：最小可接入版。

本轮确定的接口组合为：

1. OCR 识别：腾讯云 OCR 增值税发票识别。
2. 发票核验：腾讯云 OCR 增值税发票核验（新版）。
3. 凭证接入：先做标准凭证导入模板，不直接自动过账。

DeepThink 不作为图片识别工具使用。DeepThink 后续只用于票面字段出来后的业务推理、证据判断、风险解释和凭证建议。

## 二、官方资料依据

| 能力 | 推荐系统 | 官方资料 |
|---|---|---|
| 发票图片/PDF 识别 | 腾讯云增值税发票识别 | https://cloud.tencent.com/document/product/866/36210 |
| 发票真实性核验 | 腾讯云增值税发票核验（新版） | https://cloud.tencent.com/document/product/866/73674 |
| 财务软件凭证接入 | 暂不绑定具体财务软件，先用标准导入模板 | 后续按金蝶、用友、畅捷通等实际软件确认 |

## 三、为什么先选腾讯云

1. OCR 和核验同属腾讯云 OCR 产品线，账号、鉴权、SDK、错误码和测试工具更统一。
2. 官方文档提供 API Explorer，便于技术小白阶段先在线调试，再交给系统接入。
3. 发票识别与发票核验可以形成连续链路：图片识别出票面字段，再用字段发起验真。
4. 我们当前应用已经有 OCR、验真、凭证三类接口配置入口，适合最小改造。

## 四、最小接入总体流程

```text
用户上传发票图片或 PDF
  -> 后端代理接收文件
  -> 调用腾讯云 OCR 增值税发票识别
  -> 标准化为系统 Invoice 对象
  -> 用户确认或修正票面字段
  -> 后端代理调用腾讯云发票核验
  -> 写入发票闸门结果
  -> 业务追问和证据补充
  -> AI 风险初判和人工复核
  -> 生成标准凭证导入模板
  -> 财务人工导入财务软件或留存复核
```

## 五、模块一：腾讯云 OCR 发票识别

### 1. 接入目标

将当前“模拟 OCR”替换为真实 OCR 识别，但保留人工确认页。

最小结果是：用户上传发票文件后，系统能自动填入发票代码、号码、日期、金额、税额、购销方等字段。

### 2. 输入

| 字段 | 说明 |
|---|---|
| file | 发票图片或 PDF |
| fileName | 原始文件名 |
| operator | 上传人 |
| caseId | 当前业务单号，首次上传时可为空 |

### 3. 输出到本系统的字段

| 本系统字段 | 来源 |
|---|---|
| invoiceType | 腾讯云 OCR 返回的发票类型 |
| invoiceCode | 发票代码 |
| invoiceNumber | 发票号码 |
| issueDate | 开票日期 |
| seller | 销方名称 |
| buyer | 购方名称 |
| itemName | 商品或服务名称 |
| amount | 不含税金额 |
| taxAmount | 税额 |
| taxRate | 税率 |
| recognitionConfidence | OCR 置信度 |
| sourceFile | 后端保存的文件引用 |

### 4. 兜底规则

1. OCR 成功但字段不完整：进入票面确认页，由用户补齐。
2. OCR 失败：保留文件，允许手工录入。
3. OCR 置信度低于 60%：不得直接进入凭证草稿。
4. 发票类型无法识别：标记为“待人工确认”。

## 六、模块二：腾讯云发票核验

### 1. 接入目标

将当前“模拟验真”替换为真实发票核验。

最小结果是：用户确认票面字段后，系统调用腾讯云核验接口，判断发票是否真实、是否作废、是否红冲或异常。

### 2. 输入

| 字段 | 说明 |
|---|---|
| invoiceCode | 发票代码，按票种要求传入 |
| invoiceNumber | 发票号码 |
| issueDate | 开票日期 |
| amount | 不含税金额或接口要求金额 |
| checkCode | 校验码，若接口或票种要求则传 |
| invoiceType | 发票类型 |

### 3. 输出到本系统的状态

| 腾讯云核验结果 | 本系统建议状态 |
|---|---|
| 核验通过 | 验真通过 |
| 核验失败 | 验真失败 |
| 已作废 | 已作废 |
| 红冲或冲红相关状态 | 已红冲 |
| 接口超时或错误 | 待人工核验 |
| 票种不支持 | 待人工核验 |

### 4. 发票闸门规则

1. 验真通过且未重复、未红冲、未作废，才允许进入后续业务还原。
2. 验真失败、已红冲、已作废，必须进入异常工作台。
3. 接口超时不得默认为通过，只能标记为“待人工核验”。
4. 当天新开具发票可能存在同步延迟，系统应允许人工稍后重试。

## 七、模块三：标准凭证导入模板

### 1. 为什么先做模板

当前还没有确认实际财务软件，所以不应直接绑定金蝶、用友或畅捷通 API。

先做标准模板有三个好处：

1. 不依赖具体财务软件，最容易落地。
2. 财务人员可以先人工检查再导入。
3. 后续接金蝶、用友、畅捷通时，可以把模板字段直接映射到对应 API。

### 2. 模板文件

### 3. 模板字段

| 字段 | 说明 |
|---|---|
| 凭证日期 | 建议取业务确认日期或开票日期 |
| 凭证字 | 如“记” |
| 凭证号 | 可由财务软件生成，本系统可留空 |
| 摘要 | 业务事件摘要 |
| 科目编码 | 财务科目编码 |
| 科目名称 | 财务科目名称 |
| 借方金额 | 借方金额 |
| 贷方金额 | 贷方金额 |
| 币种 | 默认 CNY |
| 发票号码 | 关联发票号 |
| 发票代码 | 关联发票代码 |
| 开票日期 | 发票开票日期 |
| 销方名称 | 发票销售方 |
| 购方名称 | 发票购买方 |
| 业务类型 | 餐饮、住宿、咨询服务等 |
| 风险等级 | 低、中低、中、高 |
| 审核状态 | 待财务确认、已确认、禁止生成 |
| 附件路径 | 发票或证据文件路径 |
| 外部系统编号 | 后续导入或 API 返回编号 |
| 备注 | 人工说明 |

### 4. 凭证生成边界

1. 低风险、验真通过、证据完整：可生成凭证导入模板。
2. 中风险：必须财务确认后才能导出模板。
3. 高风险、验真失败、重复发票、红冲、作废、证据缺失：禁止生成可导入凭证。
4. 模板只是导入草稿，不代表已经过账。

## 九、开发执行步骤

### Gate T1：只做腾讯云配置页升级

- 增加腾讯云 OCR 和发票核验配置说明。
- 配置仍只保存到本地或后端环境变量，不发真实请求。
- 验收：页面能清楚显示腾讯云接入准备项。

### Gate T2：新增后端代理骨架

- 新增后端 `/api/tencent/ocr/recognize`。
- 新增后端 `/api/tencent/invoice/verify`。
- 新增环境变量读取。
- 先返回本地假响应，不接腾讯云。
- 验收：前端能通过后端代理获得标准结构。

### Gate T3：接入腾讯云 OCR

- 后端调用腾讯云 OCR。
- 将返回值映射为本系统 Invoice。
- 前端进入票面确认页。
- 验收：至少 5 张样本能识别并进入票面确认。

### Gate T4：接入腾讯云发票核验

- 用户确认票面后调用核验。
- 将结果写入发票闸门。
- 异常进入异常工作台。
- 验收：通过、失败、超时、作废或红冲场景都能正确显示。

### Gate T5：生成标准凭证导入模板

- 根据风险建议和人工确认生成 CSV。
- 禁止高风险事项导出可导入凭证。
- 验收：低风险案例导出借贷平衡模板，中高风险案例被阻断或需确认。

## 十、验收标准

1. 不懂技术的用户可以上传发票并看到自动识别字段。
2. 发票核验结果清楚显示为通过、失败、待人工核验、作废或红冲。
3. 任一接口失败不会导致页面崩溃。
4. SecretId 和 SecretKey 不出现在前端代码和浏览器 localStorage。
5. 标准凭证模板借贷平衡。
6. 高风险事项不能导出可导入凭证。
7. 真实接口调用日志可追溯。

## 十一、当前不执行事项

1. 不接自动过账。
2. 不直接写入正式财务软件。
3. 不把腾讯云密钥写进前端。
4. 不绕过票面确认和财务复核。
5. 不把 DeepThink 当 OCR 图片识别系统。
