# CO_20260718_风险驾驶舱指标下钻整改方案

## 一、问题复核

当前风险驾驶舱 `src/ui/pages/RiskDashboardPage.tsx` 中：

- “高风险金额”“待整改金额”“暂不能判断金额”只是静态指标卡。
- “发票闸门”“业务闸门”“证据闸门”“风险闸门”只是静态风险结构卡。
- 点击后不会进入对应发票明细。

当前发票列表 `src/ui/pages/InvoiceListPage.tsx` 中：

- 只支持关键词搜索。
- 不支持从风险驾驶舱带条件跳转。
- 不展示“这个金额/闸门指标由哪些发票组成”的来源说明。
- 不展示每张命中发票对应的补充提示。

## 二、整改目标

将风险驾驶舱升级为“可下钻驾驶舱”：

1. 点击“高风险金额”，跳转到发票列表并展示所有高风险发票组成。
2. 点击“待整改金额”，跳转到发票列表并展示所有闸门阻断或待补充发票组成。
3. 点击“暂不能判断金额”，跳转到发票列表并展示所有最终状态为“暂不能判断”的发票组成。
4. 点击任一闸门卡片，跳转到发票列表并展示该闸门阻断或待补充的发票组成。
5. 发票列表顶部展示筛选来源、命中数量、金额合计和“返回风险驾驶舱”入口。
6. 每张命中发票展示命中原因和补充建议，提醒使用者继续补证、补业务事实或复核风险。

## 三、统一下钻模型

### 1. URL 筛选协议

风险驾驶舱跳转到发票列表时统一使用 query 参数。

金额指标：

- `/invoices?riskFilter=high-risk`
- `/invoices?riskFilter=remediation`
- `/invoices?riskFilter=pending-judgment`

闸门指标：

- `/invoices?gate=发票闸门`
- `/invoices?gate=业务闸门`
- `/invoices?gate=证据闸门`
- `/invoices?gate=风险闸门`

后续如需扩展部门、人员、供应商、期间筛选，可继续沿用 query 参数，不新增页面。

### 2. 统一数据行

建议新增：

- `src/ui/riskDrilldown.ts`
- `src/ui/riskDrilldown.test.ts`

统一把本地 case 和演示 case 映射成同一种列表行：

```ts
interface RiskDrilldownRow {
  source: 'local' | 'demo';
  id: string;
  invoiceNumber: string;
  seller: string;
  category: InvoiceCategory;
  amount: number;
  riskLevel: RiskLevel | '待生成';
  finalStatus: WorkflowStatus;
  gates: GateCheck[];
  remediation: string[];
  detailPath: string;
  workflowPath?: string;
  matchedReasons: string[];
  nextActionHint: string;
}
```

### 3. 筛选函数

建议实现：

- `buildRiskDrilldownRows(localCases, demoCases)`
- `filterRiskDrilldownRows(rows, query)`
- `getRiskDrilldownSummary(rows, query)`
- `buildRiskDrilldownLink(filter)`

筛选规则：

- `high-risk`：`riskLevel === '高'`
- `remediation`：任一闸门 `status === '阻断' || status === '待补充'`，或存在整改建议。
- `pending-judgment`：`finalStatus === '暂不能判断'`
- `gate=发票闸门/业务闸门/证据闸门/风险闸门`：对应闸门 `status === '阻断' || status === '待补充'`

### 4. 补充建议规则

发票列表命中行应展示“下一步建议”：

- 发票闸门：重新核验票面、验真结果、重复票和红冲状态。
- 业务闸门：补充业务目的、参与人、受益人、承担理由和 AI 必答问题。
- 证据闸门：补充合同、审批、付款、验收、行程、拜访、成果物等证据链。
- 风险闸门：财务复核风险结论，必要时退回业务或证据补充。
- 高风险金额：进入三阶段处理，优先完成业务问答和证据链复核。
- 待整改金额：按命中闸门原因逐项补齐材料。
- 暂不能判断金额：补齐业务事实和证据后重新生成 AI 风险初判。

## 四、页面修改方案

### 1. 风险驾驶舱

文件：`src/ui/pages/RiskDashboardPage.tsx`

修改点：

- 金额类 KPI 卡片改为可点击链接或按钮。
- 四个闸门卡片改为可点击链接或按钮。
- 卡片文案增加“点击查看明细”。
- 卡片应保留当前视觉，但鼠标悬停要体现可点击。
- 金额和数量计算必须与下钻列表使用同一套筛选函数，避免驾驶舱金额和列表金额不一致。

### 2. 发票列表

文件：`src/ui/pages/InvoiceListPage.tsx`

修改点：

- 使用 `useSearchParams` 读取 `riskFilter` 和 `gate`。
- 当存在下钻筛选时，顶部展示筛选摘要：
  - 来源名称。
  - 命中发票数。
  - 金额合计。
  - 筛选说明。
  - 返回风险驾驶舱。
  - 清除筛选。
- 发票列表需展示命中原因和补充建议。
- 本地 case 命中时保留“继续处理”入口。
- 演示样例命中时保留“查看演示”入口。

### 3. 样式

文件：`src/styles.css`

- `.metric-card.clickable`
- `.risk-tile.clickable`
- `.drilldown-banner`
- `.drilldown-reason-list`
- `.next-action-hint`
- `.filter-chip`

要求：

- 不破坏现有卡片布局。
- 卡片可点击区域要清楚。
- 移动端不发生文本重叠。

## 五、测试要求

至少补充：

1. 高风险金额筛选：筛出的行 riskLevel 都为“高”，金额合计等于对应发票金额之和。
2. 待整改金额筛选：筛出的行至少有一个闸门阻断或待补充。
3. 暂不能判断金额筛选：筛出的行 finalStatus 都为“暂不能判断”。
4. 四个闸门筛选：点击任一闸门，对应列表只包含该闸门阻断或待补充的发票。
5. 风险驾驶舱指标金额与下钻列表金额一致。
6. 下钻行能生成 `nextActionHint`，用于提醒使用者补充材料或重新判断。
