# CO_20260718_流程交互与AI风险初判整改方案

## 一、整改背景

用户在三阶段流程使用中发现 4 个体验和功能缺口：

1. 业务追问环节展示了“映射字段：externalParty”等内部字段，不适合面向使用者。
2. 证据补充环节只有示例材料说明，没有可下载模板。
3. 点击“生成 AI 风险初判”后虽然进入第 6 步，但界面没有明确展示 AI 初判风险分析、建议或报告。
4. 7 个流程环节只能向前推进，步骤条不可点击，缺少回看和退后机制。

## 二、整改目标

本轮只处理上述 4 个问题，不扩大到 OCR、验真、凭证接口或完整后端模板库。

目标效果：

- 业务追问页不再暴露内部技术字段。
- 证据补充页为每项示例材料提供“AI 生成模板下载”。
- AI 风险初判生成后，必须在页面展示结构化风险初判报告。
- 7 个步骤支持鼠标点击跳转，已完成步骤可回看，未满足前置条件的步骤应阻断并提示原因。

## 三、功能设计

### 1. 业务追问字段清理

位置：`src/ui/pages/InvoiceWorkflowPage.tsx`

处理方式：

- 删除业务追问问题头部中的 `映射字段：{q.mappedField}`。
- 不删除 `StructuredQuestion.mappedField` 类型和 mock 数据，因为该字段仍可作为内部业务事件映射依据。
- 页面只保留“问题文本、为什么问、建议准备、输入框”。

验收标准：

- 页面不出现“映射字段”。
- 页面不出现 `externalParty`、`participants`、`purpose` 等英文内部字段。
- 业务问答硬闸门逻辑保持不变。

### 2. 证据模板下载

新增建议文件：

- `src/ai/mockEvidenceTemplateService.ts`
- `src/ai/mockEvidenceTemplateService.test.ts`

模板生成方式：

- 由模拟 AI 根据发票类别、证据名称、证明目的、缺失影响、示例材料生成 Markdown 模板。
- 前端点击“生成模板”后创建浏览器 Blob URL，并展示“下载模板”链接。
- 下载文件名建议：`发票类别-证据名称-模板.md`。
- 模板内容应包含：
  - 标题。
  - 适用发票类别。
  - 证明目的。
  - 填写说明。
  - 需填写字段清单。
  - 附件清单。
  - 经办人确认区。
  - 财务复核区。

页面交互：

- 每项证据材料下增加“AI 生成模板”按钮。
- 生成后显示：
  - 下载链接：`下载模板`
  - 下载地址：当前 Blob URL 或“已生成本地下载链接”
- 已生成的模板链接按证据名称缓存到组件 state。

验收标准：

- 每一项证据指导材料都有模板生成入口。
- 点击后能下载 `.md` 模板。
- 模板文本不是空文件，且包含证据名称、证明目的、缺失影响和填写清单。

### 3. AI 风险初判报告

现状问题：

- `GENERATE_AI_RISK` 会写入 `风险解释` AI 介入记录，并推进到“人工复核”。
- 但页面主要只展示右侧 AI 辅助判断摘要，用户感知不到完整的初判报告。

整改方式：

- 新增风险初判报告渲染区，建议放在：
  - 第 5 步“AI风险初判”按钮下方：展示“生成后将在下一步展示报告”的提示。
  - 第 6 步“人工复核”顶部：展示最近一次 `stage === '风险解释'` 的完整初判报告。
- 报告内容不依赖第 7 步 `decisionDraft`，应基于当前 session 实时计算：
  - 风险等级。
  - 置信度。
  - 四道闸门状态和原因。
  - 发票风险点。
  - 业务逻辑判断。
  - 证据链缺口。
  - AI 建议动作。
  - 是否允许人工采纳/修改，或只能退回补充。

可选实现：

- 在 `InvoiceWorkflowPage.tsx` 中新增 `renderRiskPrecheckReport()`。
- 复用 `mockAssessRiskLevel` 和 `mockEvaluateGates`。
- 不必新增领域类型；报告可以是 UI 层派生视图。

验收标准：

- 点击“生成 AI 风险初判”后进入第 6 步。
- 第 6 步页面立即展示“AI 风险初判报告”。
- 报告包含风险等级、置信度、闸门判断、风险点和处理建议。
- 如果业务问答或证据缺失，报告必须明确提示“不得采纳/修改，只能退回补充”。

### 4. 7 步点击跳转机制

位置：`src/ui/pages/InvoiceWorkflowPage.tsx`

设计原则：

- 步骤条从纯展示 `div` 改为可点击 `button`。
- 已完成步骤和当前步骤可以点击查看。
- 未来步骤只有在前置条件满足时才允许跳转。
- 未满足条件时不跳转，并在页面显示原因。

建议新增 action：

- `NAVIGATE_STEP`
  - 参数：`step: WorkflowStep`
  - 用途：只切换 `currentStep`，不改 `finalStatus`，不改业务判断，不生成 AI 结果。

建议新增校验函数：

- `canNavigateToStep(session, targetStep)`
- `explainStepNavigationBlock(session, targetStep)`

基础规则：

- 第 1 步 `发票输入`：流程页中可点击但建议跳回 `/intake`，不在当前会话内处理。
- 第 2 步 `票面确认`：当前 case 可回看。
- 第 3 步 `业务追问`：票面确认后可进入。
- 第 4 步 `证据补充`：业务必答问题完成后可进入。
- 第 5 步 `AI风险初判`：已提交证据后可进入。
- 第 6 步 `人工复核`：已生成 AI 风险初判后可进入。
- 第 7 步 `生成建议`：人工复核已采纳/修改且未被硬阻断后可进入。

验收标准：

- 点击已完成步骤能切换对应内容。
- 点击未满足条件的未来步骤不跳转，并显示阻断原因。
- 步骤切换不破坏 `finalStatus`、`completedSteps` 和操作日志。
- 回看旧步骤后仍可继续从当前业务状态推进。

## 四、测试要求

至少新增或更新测试：

1. 模板服务测试：不同证据项能生成非空 Markdown 模板。
2. 模板内容测试：包含证据名称、证明目的、缺失影响、填写清单。
3. 步骤导航 reducer 测试：`NAVIGATE_STEP` 只改 `currentStep`，不改 `finalStatus`。
4. 步骤导航阻断测试：业务问答未完成时不能跳到证据补充。
5. AI 风险初判测试：生成后存在 `风险解释` AI 介入记录，人工复核页可派生风险等级和闸门报告。

## 五、验收命令

T/IT 修改完成后必须执行：

```bash
git diff --check
npm test
npm run build
npm audit --omit=dev
```

如能启动本地预览，应返回预览地址，并重点点验：

- 业务追问页面不显示内部字段。
- 证据补充模板可下载。
- AI 风险初判报告可见。
- 点击 7 个步骤时能按规则跳转或给出阻断原因。

## 六、边界说明

- 本轮模板为浏览器本地 AI 模拟生成，不接真实文件服务器。
- Blob 下载地址只在当前浏览器会话有效，作为 MVP 下载链接使用。
- 不改变 Gate 3 已建立的业务问答硬闸门、证据闸门和入账科目建议逻辑。
