## 一、已确认决策

1. 首期路线：选择 B，业务闭环 MVP 优先。
2. 产品名称：统一为“发票溯源证据链系统”。
3. 首期终端：一期只做电脑端，手机端仅预留入口和未来扩展位置。
4. 手机端边界：一期不开发手机端财务审核；未来手机端优先作为员工上传、确认、补证据入口。
5. 场景范围：一期采用“八类覆盖、三类做深”。
6. 三类做深：餐饮费、住宿费、咨询服务费。
7. 外部接口：第一版允许 OCR、验真、凭证接口先用模拟数据跑通，后续再接真实接口。
8. 开发前置：进入正式开发前先初始化 Git 版本管理并完成 GitHub 备份。

## 二、产品一句话定义

发票溯源证据链系统，是一个以发票为入口、自动还原真实业务、补齐证据链、判断财税风险并生成凭证草稿的智能入账决策系统。

## 三、产品定位

本系统不是单纯的发票 OCR 工具，也不是传统报销系统。它的核心价值在于把“发票能不能入账”拆成四个连续判断：

1. 发票是否真实、有效、完整。
2. 发票背后的业务是否真实、合理、与经营相关。
3. 证据链是否足以证明业务事实。
4. 会计和税务处理是否安全，是否可以生成凭证草稿。

系统最终要做到：业务人员提供事实，系统组织证据，AI还原业务，规则引擎判断合规边界，财务人员处理异常，管理人员监督风险。

## 四、核心业务闭环

首期业务闭环如下：

1. 上传或录入发票。
2. 系统模拟 OCR 识别票面信息。
3. 系统模拟验真、查重、红冲和基础异常识别。
4. 系统判断发票所属业务类型。
5. 系统根据场景提出业务事实问题。
6. 用户补充业务事实和证据材料。
7. 系统形成标准业务事实。
8. 系统检查证据链完整性。
9. 系统根据规则输出会计、税务、内控和证据结论。
10. 系统生成风险卡片和整改建议。
11. 低风险事项生成凭证草稿。
12. 高风险、低置信度、资料不足事项进入人工复核或暂不能判断。
13. 人工修改结果留痕，作为后续企业规则学习依据。

## 五、首期用户角色

### 1. 经办人员

一期在电脑端完成操作，未来可扩展到手机端。

主要操作：

- 新增发票。
- 确认票面字段。
- 回答业务事实问题。
- 上传或补充证据材料。
- 查看退回原因、资料缺口和处理状态。

### 2. 财务人员

财务人员是首期电脑端的核心用户。

主要操作：

- 查看异常工作台。
- 处理发票异常、业务不清、证据不足、税务风险。
- 审核单张发票三阶段结果。
- 查看事实依据、证据依据和规则依据。
- 确认、修改或退回系统结论。
- 生成或驳回凭证草稿。

### 3. 管理人员

管理人员在首期查看电脑端风险驾驶舱。

主要操作：

- 查看整体风险金额和事项数量。
- 查看部门、人员、供应商风险。
- 查看高风险事项和待整改事项。
- 查看 AI 判断采纳率、人工修改率、凭证草稿通过率。
- 维护或确认风险阈值和审批边界。

### 4. 规则管理员

规则管理员作为管理权限，不作为独立业务端。

主要操作：

- 维护场景规则。
- 维护证据清单。
- 维护会计科目映射。
- 维护审批阈值。
- 维护企业个性化规则。

## 六、首期页面结构

### 1. 工作台首页

面向财务人员和管理人员，展示：

- 今日待处理事项。
- 发票异常数量。
- 业务不清数量。
- 证据不足数量。
- 高风险事项数量。
- 待生成凭证草稿数量。
- 暂不能判断事项数量。

### 2. 发票列表

展示所有发票的状态：

- 待识别。
- 待确认票面。
- 待还原业务。
- 待补充证据。
- 待风险判断。
- 待财务复核。
- 待负责人审批。
- 凭证草稿已生成。
- 已完成。
- 已退回。
- 暂不能判断。
- 已作废或已红冲。

### 3. 单张发票三阶段处理页

页面顶部固定为：

发票识别 -> 业务还原 -> 入账风险

#### 第一阶段：发票识别

展示：

- 发票图片或附件占位。
- 结构化票面字段。
- 模拟验真结果。
- 查重结果。
- 红冲关系。
- 票面异常。
- 发票分类。
- 字段置信度。

#### 第二阶段：业务还原

展示：

- 候选业务场景。
- 动态问题。
- 业务事实表。
- 已上传证据。
- 缺失证据。
- 证据完整度。
- 业务矛盾提示。
- 业务还原置信度。

#### 第三阶段：入账风险

展示：

- 总体处理结论。
- 风险卡片。
- 会计处理建议。
- 增值税处理建议。
- 企业所得税处理建议。
- 其他税种触发提示。
- 内控制度结论。
- 事实、证据和规则依据。
- 凭证草稿。
- 人工复核记录。

### 4. 异常工作台

按队列组织：

- 发票异常。
- 业务不清。
- 证据不足。
- 税务风险。
- 关联方和股东支出风险。
- 重复报销风险。
- AI 低置信度事项。
- 凭证草稿队列。

### 5. 风险驾驶舱

展示：

- 发票数量和金额。
- 高风险金额。
- 待整改金额。
- 暂不能判断金额。
- 风险类型结构。
- 部门风险排行。
- 人员风险排行。
- 供应商风险排行。
- AI 判断采纳率。
- 人工修改率。
- 凭证草稿一次通过率。

### 6. 手机端预留入口

一期不开发完整手机端，仅在产品和系统结构上预留：

- 手机上传入口占位。
- 手机端经办人任务入口占位。
- 未来手机端 API 边界。
- 响应式布局基础考虑。

不做：

- 手机端财务审核。
- 手机端管理驾驶舱。
- 手机端复杂规则配置。

## 七、一期场景范围

### 1. 八类覆盖

八类发票均要能识别、分类、进入状态流转并输出基础判断：

1. 餐饮费。
2. 住宿费。
3. 交通出行费。
4. 车辆相关费用。
5. 办公用品。
6. 咨询及服务费。
7. 广告宣传及推广费。
8. 租赁及物业费用。

### 2. 三类做深

首期重点做深：

1. 餐饮费。
2. 住宿费。
3. 咨询及服务费。

这三类需要具备完整闭环：

- 业务场景判断。
- 动态追问。
- 证据清单。
- 缺口识别。
- 风险卡片。
- 会计建议。
- 税务建议。
- 凭证草稿。
- 人工复核留痕。

## 八、三类做深规则方向

### 1. 餐饮费

重点判断：

- 是业务招待、员工聚餐、会议餐、差旅餐，还是个人消费。
- 是否有客户、业务事项、参与人员、审批记录。
- 是否存在股东、家庭成员、关联方个人消费嫌疑。

典型结论：

- 证据完整且业务合理：可生成凭证草稿。
- 客户和业务目的不清：需补资料。
- 个人消费嫌疑：高风险，转人工复核。

### 2. 住宿费

重点判断：

- 是否对应出差、会议、培训、项目现场或客户拜访。
- 是否有出差申请、行程、人员、地点和业务目的。
- 发票日期、地点、人员是否相互匹配。

典型结论：

- 与出差事实匹配：可生成凭证草稿。
- 无出差记录或地点矛盾：需补资料或转人工。
- 家属或非业务人员住宿：高风险。

### 3. 咨询及服务费

重点判断：

- 是否有合同、服务成果、验收记录、付款记录。
- 服务内容是否真实、必要、与经营相关。
- 交易对手是否异常。
- 金额是否明显异常。

典型结论：

- 合同、成果、验收完整：可生成凭证草稿。
- 无合同无成果：高风险。
- 交易对手异常或关联方交易：升级复核。

## 九、产品验收标准

首期产品达到以下标准即为通过：

1. 电脑端可以完整进入工作台、发票列表、三阶段处理页、异常队列、风险驾驶舱。
2. 八类发票均可录入、分类、流转并输出基础结论。
3. 餐饮、住宿、咨询服务三类可完成完整闭环。
4. 每张发票都能形成发票对象、业务事件对象、证据链对象、风险决策对象。
5. 高风险事项不会自动生成凭证草稿。
6. 资料不足事项能明确提示补充材料。
7. 低风险标准事项可生成凭证草稿。
8. 所有结论都能看到事实依据、证据依据和规则依据。
9. 人工修改和复核意见有留痕。
10. 手机端入口已预留，但不作为一期验收主功能。

## 十、产品后续路线

### 第二期

- 接入真实 OCR。
- 接入真实发票验真。
- 接入真实凭证或财务软件接口。
- 扩展手机端员工入口。
- 增加更多发票类型的深度规则。

### 第三期

- 建设企业个性化规则学习。
- 增强交易对手画像。
- 接入银行流水、合同、采购、报销系统。
- 支持更多税种和行业场景。

### 第四期

- 支持多企业、多组织、多角色权限。
- 支持 SaaS 化或私有化部署。
- 建设完整审计追踪和企业风险画像体系。
